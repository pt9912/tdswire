# Massenladen mit d-migrate gegen den Testserver: Messprotokoll vom 2026-11-07

Messprotokoll zu [TDS-FA-12](../../spec/lastenheft.md#tds-fa-12--testserver-mit-veränderlichem-arbeitsspeicher-bestand-und-prüfclient-d-migrate) und [TDS-FA-11](../../spec/lastenheft.md#tds-fa-11--mitgeliefertes-simulations-backend) (`AGENTS.md` §5 Regel 7), Träger: [slice-schreibpfad-bulk-load](../plan/planning/in-progress/slice-schreibpfad-bulk-load.md). Es hält fest, was gemessen wurde, nicht, ob eine Anforderung belegt ist. Es setzt den [Spike der Callback-Lösung](callback-loesung-spike-2026-11-05.md) fort: dort lief das Massenladen gegen einen Wegwerf-Prototyp, hier gegen die Bibliothek und den Bestand des Testservers, wie sie im Repo liegen.

**Vorbehalt, der für jede Zeile gilt.** Gemessen ist das Verhalten von d-migrate 1.12.0 und mssql-jdbc 13.4.0 gegen den **Testserver**, nicht gegen einen echten SQL Server (kein Lauf gegen ihn; die EULA-Entscheidung liegt beim Nutzer, Träger der Gegenmessung: [slice-qa-vergleichslauf-d-messungen-bulk-merge](../plan/planning/open/slice-qa-vergleichslauf-d-messungen-bulk-merge.md)). Die Antworten des Servers auf `INSERT BULK` und auf die Nachricht 0x07, die Überführung der Werte und die Fehlernummer sind Setzungen, die der Client hier angenommen hat; ein echter Server kann anders antworten. Die Zeiten sind Einzelmessungen auf einem Rechner unter wechselnder Last; sie vergleichen Läufe untereinander, sie sind keine Leistungszusage.

## Aufzeichnung: was d-migrate beim `data import` sendet

`data import --target <url> --source kunden.json --table kunden` (3 Zeilen, Standardpfad), Reihenfolge der Texte am Testserver (SQL-Texte, gekürzt auf das Wesentliche; Zeilenumbrüche als `\n`):

1. `SELECT 1`, `SET LOCK_TIMEOUT 30000`, ein Text mit sieben `SET`-Anweisungen, `SELECT SCHEMA_NAME() AS schema_name` (Form C und K, schon vorhanden);
2. `SELECT * FROM [dbo].[kunden] WHERE 1 = 0`, `sys.identity_columns`, `sys.computed_columns` je mit Parameter `OBJECT_ID( @P0 )` (Form K);
3. `set implicit_transactions on` (Form C);
4. `set fmtonly on SELECT [Id], [Name], [Eintritt] FROM [dbo].[kunden] WHERE 1 = 0\nset fmtonly off`;
5. `sp_executesql N'SET FMTONLY ON SELECT * FROM [dbo].[kunden] '` als **SQL-Text**, nicht als RPC;
6. `select collation_name, is_computed from sys.columns where object_id=OBJECT_ID('[dbo].[kunden]') order by column_id ASC` (der Name als Literal);
7. `INSERT BULK [dbo].[kunden] ([Id] BIGINT , [Name] NVARCHAR(4000) , [Eintritt] VARCHAR(10) )  with (CHECK_CONSTRAINTS, FIRE_TRIGGERS, ROWS_PER_BATCH = 3)`, danach die Nachricht 0x07 mit den drei Zeilen;
8. `INSERT BULK` mit demselben Text, danach eine Nachricht 0x07 **ohne Zeile** (zweite Nachricht); `IF @@TRANCOUNT > 0 COMMIT TRAN`; `SELECT SCHEMA_NAME()`; `sys.identity_columns` mit `TOP 1`; `set implicit_transactions off IF @@TRANCOUNT > 0 COMMIT TRAN`.

Gegenüber dem Spike neu gemessen: jede Nachricht 0x07 steht hinter einem eigenen `INSERT BULK` (auch der Schlussteil ohne Zeile); das Ziel bleibt in der Bibliothek trotzdem nach einer Nachricht stehen (Setzung, `SPEC-001`). Nutzlast der ersten Nachricht 0x07 (Hex):

Gelesen von Hand nach `MS-TDS` (2.2.7.4 COLMETADATA, 2.2.7.17 ROW, 2.2.7.6 DONE): COLMETADATA mit 3 Spalten, `Id` als `INTN` (8 Byte, Flags 0: nicht nullbar), `Name` als `NVARCHAR` (8000 Byte, Kollation `0904D00034`), `Eintritt` als `BIGVARCHAR` (10 Byte, Text `2026-01-02`; der Treiber sendet ein `DATE` als `VARCHAR(10)`); dann drei ROW (die zweite mit `ffff ffff` für zwei NULL), dann DONE mit Status 0 und Zeilenzahl 0. Die zweite Nachricht trägt dieselbe COLMETADATA und gleich danach DONE.

## Ergebnis je Lauf

Alle Befehle: `docker run --rm --network host -v <Arbeitsverzeichnis>:/work <Image> <Befehl>`, `<url>` wie oben; A und B sind die beiden Testserver.

| Nr. | Befehl (gekürzt) | Exit | Ergebnis |
|---|---|---|---|
| L1 | `data import --target A --source kunden.json --table kunden` (3 Zeilen: Umlaute, NULL, Datum) | 0 | „3 inserted“; `data export --format json` danach: dieselben drei Zeilen (`Ada Ünï`, NULL in `Name` und `Eintritt`, `Cäcilie`) |
| L2 | `data import … bestellungen.json --table bestellungen` (`Betrag` 12.50, 7.25, NULL) | 0 | „3 inserted“; Export: `"12.50"`, `"7.25"`, `null` |
| L3 | `data transfer --source A --target B --tables kunden,bestellungen` | 0 | „Transferred: kunden“, „Transferred: bestellungen“; Export von B und A: `cmp` ohne Unterschied (byte-gleich) |
| L4 | `schema migrate --source soll.yaml --target db:A --execute --report …` (Soll mit der Tabelle `typen`: `BIGINT`, `NVARCHAR(4000)`, `DECIMAL(10,2)`, `BIT`, `DATE`, `TIME`, `DATETIME2`), dann `data import … typen.json --table typen` | 0 und 0 | „3 inserted“; Export: `Preis` `"12.50"`, `Aktiv` `true`/`false`/`null`, `Eintritt` `"2026-01-02"`, `Zeit` `"13:14:15"`, `Stempel` `"2026-01-02T13:14:15"`, die NULL-Zeile |
| L5 | dasselbe Soll gegen B (`schema migrate --execute`), `data transfer --source A --target B --tables typen` | 0 und 0 | „Transferred: typen“; Export von B und A byte-gleich |

| L7 | `data import … fehler.json --table kunden --chunk-size 2` (6 Zeilen mit den Schlüsseln 4, 5, 6, 1, 8, 9; die vierte wiederholt den Schlüssel 1) | 5 | Nachricht 1 („2 rows processed, 2 inserted“), dann „Import failed: Backend error.“; Export: Schlüssel 1 bis 5 |

| H4 | 150 000, 150 000 (eine Nachricht von rund 19,8 MB, gerechnet) | `-Xmx256m` | 5 | „Import failed: Broken pipe“: die Nachricht über 16 MiB schließt die Verbindung (Grenze von `SPEC-007`, wie b11); der Server läuft weiter, der nächste Import (3 Zeilen) endet mit Exit 0 |

Auswertung der vier Messpunkte des Slice:

- **(i) Zeilenzahl und Inhalt:** L1 bis L5 stimmen nach `data import` und `data transfer` (Zeilenzahl, Inhalt, NULL, Umlaute), die Exporte von A und B sind byte-gleich.
- **(ii) Fehler mitten im Strom:** d-migrate erhält bei einer abgewiesenen Nachricht „Backend error.“ und endet mit Exit 5 (L6, L7). Die Fehlernummer 50004 (Setzung der Bibliothek, `TDS_BACKEND_ERROR`) wurde in diesem Lauf nicht aus dem JDBC-Log gelesen; gemessen ist sie im Spike (b5). Neu gegenüber dem Spike: die **Nachricht ist atomar** (L7): die Nachricht davor bleibt im Bestand, die fehlerhafte steht nicht darin (Schlüssel 6 fehlt trotz der Zeile vor dem doppelten Schlüssel), die folgende wird nicht gesendet. Das gilt nur, weil der Bestand des Testservers den Stapel atomar übernimmt ([ADR-0033](../plan/adr/0033-callback-loesung-fuer-schreiben-struktur-und-massenladen.md) Nr. 6).
- **(iii) Typen:** `BIGINT`, `NVARCHAR(4000)`, `DECIMAL(10,2)`, `BIT`, `DATE`, `TIME` und `DATETIME2` laufen im Standardpfad von `data import` und von `data transfer` (L4, L5); `INT` scheitert im Treiber (L8). Nicht gemessen: `SMALLINT`, `TINYINT`, `FLOAT`, `UUID`, Binärtypen, `NVARCHAR(MAX)`, Dezimalzahl mit Precision über 10, Zeit mit Nachkommastellen.
- **(iv) Beschränkter Speicher:** Der Speicherbedarf des Servers wird vom **Bestand** bestimmt, nicht vom Massenladen: 100 000 Zeilen brauchen unter 64 MiB (H1), 500 000 brauchen mehr als 64 MiB und weniger als 256 MiB (H2, H3). Die Nachricht gilt als Ganzes (Obergrenze 16 MiB, H4); der Gegendruck des Integrators wirkt zwischen den Nachrichten, weil die Bibliothek die nächste erst nach der Antwort liest (nicht gesondert gemessen, im Spike b13).

## Mutationsnachweise

Je Wächter eine Mutation am geprüften Code, ein Lauf der Tests des Wächters in einem Wegwerf-Abbild (Gradle in Docker, Stufe auf `deps`, Mutation mit `sed`, danach zurückgesetzt; der Erzeuger liegt nicht im Repo), Ergebnis aus dem Gradle-Log gelesen. Die Spalte „Rot“ nennt die roten Testfälle (nicht alle roten, höchstens die ersten vier des Logs); jede Mutation war am Stand dieses Slice vor der Closure grün übersetzbar und ihr Test lief.

| Nr. | Zusage | Mutation | Rot |
|---|---|---|---|
| M01 | eine abgeschnittene Nachricht ist ein Fehler (DONE wird verlangt) | der Leser gibt die Zeilen zurück, sobald die Nachricht endet | `BulkLoadReaderTest`: „eine fehlerhafte Struktur …“, „jede Teilnachricht ist ein Fehler des Lesers“ |
| M02 | das IGNORE-Bit verwirft die Nachricht | das Bit wird nicht gelesen (`false` statt `message.ignore`) | `BulkDispatchTest`: „das IGNORE-Bit verwirft die Nachricht …“ |
| M03 | `INSERT BULK` setzt ein Ziel, jede andere Anfrage löscht es | `statement` setzt das Ziel nicht zurück | `BulkDispatchTest`: „das Ziel bleibt bis zur naechsten anderen Anfrage“ |
| M04 | ein RPC beendet das Massenladen | `RequestLoop` ruft `bulk.clear()` nicht | `BulkDispatchTest`: „das Ziel bleibt bis zur naechsten anderen Anfrage“ |
| M05 | ein Wert wird in den Typ der Spalte überführt | `Int32` reicht den Wert unverändert durch | `SimulationBackendBulkTest`: „ein Wert, der nicht passt …“, „die Zeilen gehen in einem Aufruf …“ |

| M07 | ein ungültiger Wert ruft keinen Callback | der ungültige Wert wird übersprungen | `SimulationBackendBulkTest`: „ein Wert, der nicht passt, ruft keinen Callback“ |

| M09 | der Schlüssel ist eindeutig (Bestand) | keine Prüfung des Schlüssels | `TableStoreTest`: „eine fehlerhafte Nachricht …“, „Dezimal- und Textschluessel sind eindeutig …“ |

| M14 | der Zeitpunkt gilt auch mit Leerzeichen | das Leerzeichen gilt nicht | `SimulationBackendBulkTest`: „die Zeilen gehen in einem Aufruf …“; `SimValuesTest`: „Datum Zeit und Zeitpunkt nur im ISO-Format“ |

## Grenzen der Messung

- Einzelmessungen auf einem Host unter Last, ein Digest des Clients, eine Treiberversion; die Zeiten haben keine Streuung.
- Nicht gemessen: ein Lauf gegen einen echten SQL Server (die Antwort auf `INSERT BULK` und auf die Nachricht 0x07, die Nummer und der Text von Fehlern, die Wirkung von `FMTONLY`), Parquet und CSV, mehr als zwei gleichzeitige Verbindungen, Abbruch durch den Nutzer (ATTENTION) während des Massenladens, TLS, `--on-conflict skip|update` (Träger: [slice-schreibpfad-merge-output](../plan/planning/open/slice-schreibpfad-merge-output.md)).
- Die Hex-Nutzlast ist der Mitschnitt einer Instrumentierung, die nicht im Repo liegt; der Lauf ist nicht byte-genau wiederholbar (Sitzungs- und Lauf-Kennungen), die Nutzlast der Nachrichten ist es für dieselbe Eingabe.
- Aufgeräumt nach den Läufen: die Testserver-Container und die Hilfs-Container mit begrenztem Heap entfernt.
