# Spezifikationszeile und Bau weiten eine Liste, die angenommene ADRs schließen, vor der Folge-ADR

**Sub-Area:** `*` (Simulations-Backend, ADRs)

Der Plan führt als Start-Bedingung eine Folge-ADR zu einer Liste, die angenommene ADRs als abschließend führen ([ADR-0012](../../../../adr/0012-simulations-backend-beschreibung-und-formen.md) Entscheidung 14, [ADR-0033](../../../../adr/0033-callback-loesung-fuer-schreiben-struktur-und-massenladen.md) Nr. 11). Die Nutzerentscheidung „begrenzt auf erkannte Formen“ wird beim Bau als Deckung einer neuen Kombination bekannter Formen gelesen; Spezifikationszeile (S2) und Code entstehen vor der ADR, der Review findet die offene Frage, der Architect schreibt die ADR nach dem Bau, der Nutzer nimmt sie an. Zwischen Bau und Annahme trägt die Form keinen ADR-Träger, und eine Verwerfung ließe Spezifikation, Code und Tests ohne ihn. Prüfpunkt für die Planung: eine Nutzerentscheidung, deren Lesart eine Folge-ADR braucht, nennt im Slice, ob der Bau vor oder nach der Annahme beginnt; beginnt er davor, steht die Annahme in der DoD. Verwandt, eigener Mechanismus: `BEO-TDS/neue-adr-weitet-liste-einer-accepted-adr-ohne-supersedes` (dort sagt die ADR nichts zum Verhältnis, hier fehlt die ADR beim Bau) und `BEO-TDS/lesart-einer-nutzerentscheidung-unbestaetigt`.
