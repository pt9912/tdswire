# Die Angleichung des Katalogs an Standardwert, Eindeutigkeit, Fremdschlüssel, Index und Prüfbedingung hat benannte Grenzen gegen den echten SQL Server ohne Träger

**Sub-Area:** `*` (Simulations-Backend, Katalog, Strukturänderung, Beschreibungsdatei des Testservers)

Der Slice [slice-katalog-indizes-defaults-fremdschluessel](../../../done/slice-katalog-indizes-defaults-fremdschluessel.md) beantwortet die Katalogabfragen von d-migrate für diese Elemente aus den mitgeteilten Tabellen und erkennt die Strukturformen D1 bis D4 ([`SPEC-036`](../../../../../../spec/spezifikation.md#spec-036--erkannte-anweisungsformen-des-simulations-backends-vorläufig)). Maßstab des Nutzers: die Spezifikation ist Zielbild, der echte SQL Server die Referenz. Folgende Abweichungen vom Zielbild sind gemessen oder aus der Dokumentation des Servers bekannt und stehen als Grenze in der Spezifikation:

1. **Standardwert an vorhandener Spalte:** `schema migrate --execute` sendet dafür einen Text mit `DECLARE @df sysname …`; er ist nicht erkannt, der Lauf endet mit Exit 5 (`Unsupported SQL.`, gemessen am Testserver, Messprotokoll Zeile c1). Ein Standardwert in `CREATE TABLE` oder an einer neuen Spalte ist nicht betroffen.
2. **`ALTER TABLE … DROP CONSTRAINT [IF EXISTS]`:** gebaut als Form D5 ([`SPEC-036`](../../../../../../spec/spezifikation.md#spec-036--erkannte-anweisungsformen-des-simulations-backends-vorläufig)); ein zweites `schema migrate --execute` mit einer Prüfbedingung im Soll endet mit Exit 0 und `IDENTICAL`, wie am echten Server (Messprotokoll [drop-constraint-d-migrate-2026-11-11](../../../../../messungen/drop-constraint-d-migrate-2026-11-11.md)). Grenzen der Form (Punkte 10 bis 12 unten): der Name eines Standardwerts und der des Schlüssels sind im Modell nicht geführt und treffen nicht (der echte Server entfernt die Bedingung); nach 3728 und 3733 sendet der Server ein zweites ERROR (3727), die Bibliothek nicht; ein Fremdschlüssel auf den Schlüssel hindert das Entfernen nicht (3725 am echten Server, keine referentielle Integrität in der Bibliothek).
3. **Index mit `unique: true`:** keine Abweichung des Testservers. d-migrate liest `CREATE UNIQUE INDEX` als Eindeutigkeit zurück; `schema migrate` endet mit `POST_EXECUTE_DRIFT` und Exit 5, am Testserver und am echten Server (2022 und 2025) gleich (Messprotokoll, Schritte s14 und s15 und Tabelle C).
4. **Prüfbedingung aus der Beschreibungsdatei roh:** der Katalog meldet den Text der Datei (`"Menge">(0)` wie `schema reverse` ihn schreibt), nicht die Form des Servers (`([Menge]>(0))`); nur eine Strukturänderung über die Bibliothek erzeugt die Form des Servers.
5. **Namen von Bedingungen:** die Bibliothek verlangt sie je Tabelle eindeutig, der SQL Server nach seiner Dokumentation je Schema (nicht gemessen); d-migrate vergibt in `ALTER TABLE` Namen ohne die Tabelle (`_fk_KundeId`).
6. **Ausdruck einer Prüfbedingung:** `< =`, `> =` und `< >` mit Leerraum gelten als `<=`, `>=`, `<>` (Grammatik von T-SQL nicht gemessen); die Spalten im Ausdruck werden nicht gegen die Tabelle geprüft.
7. **Reihenfolge von Namen:** die Antworten ordnen Namen ohne Beachtung der Schreibweise, der Server nach der Kollation der Datenbank (nicht gemessen).
8. **Antwortspalten der übrigen Katalogformen:** `FULLTEXT_COLUMNS`, `PARTITIONING`, `SEQUENCES` und `VIEW_COLUMNS` sind mit denselben Aufnahmen gemessen (Typen und Nullbarkeit), aber nicht angeglichen; sie antworten leer mit den Spalten der Setzung.
9. **`DROP INDEX [IF EXISTS]`:** gebaut als Form D6 ([`SPEC-036`](../../../../../../spec/spezifikation.md#spec-036--erkannte-anweisungsformen-des-simulations-backends-vorläufig)); ändert das Soll einen vorhandenen Index, sendet d-migrate vor dem `CREATE INDEX` den Text `DROP INDEX IF EXISTS [<Name>] ON [<Tabelle>];`, der echte Server antwortet mit `DONE` und dem Befehl `0x00c9`, und ein zweites `schema migrate --execute` mit geändertem oder umbenanntem Index endet am Testserver mit Exit 0 und `IDENTICAL` (Messprotokoll [drop-index-d-migrate-2026-11-11](../../../../../messungen/drop-index-d-migrate-2026-11-11.md)). Grenzen der Form: Punkte 13 und 14.
10. **Zweites ERROR 3727 nach 3728 und 3733:** der echte Server sendet nach `DROP CONSTRAINT` eines Namens ohne Treffer (3728) oder einer Bedingung einer anderen Tabelle (3733) ein zweites ERROR 3727 („Could not drop constraint. See previous errors.“); die Bibliothek sendet nur das erste. Der Mechanismus eines Folge-Tokens nach dem ERROR existiert (INFO 3621 nach 2628, [`SPEC-031`](../../../../../../spec/spezifikation.md#spec-031--streaming-fehler-und-atomarität)). Gemessen nur als Batch (nicht im RPC). Trigger: ein Client, der das zweite ERROR auswertet, oder ein Fund der Abnahme.
11. **Name von Standardwert und Schlüssel:** das Modell führt keinen Namen für einen Standardwert und für den Schlüssel; `DROP CONSTRAINT <df-/pk-Name>` trifft sie am Testserver nicht (3728), am echten Server fällt die Bedingung. Die Fläche wird nicht erweitert ([ADR-0046](../../../../adr/0046-oeffentliche-flaeche-der-katalog-elemente.md), Option A bleibt); d-migrate sendet für den Standardwert den Text mit `DECLARE @df …`, nicht `DROP CONSTRAINT <Name>`. Dasselbe gilt für den Namen des Schlüssels in `DROP INDEX <Schlüssel> ON …`: der Server antwortet 3723 (State 4), die Bibliothek 3701 (mit `IF EXISTS` Erfolg). Entscheid des Nutzers (Folge-Entscheid zu [ADR-0046](../../../../adr/0046-oeffentliche-flaeche-der-katalog-elemente.md)), falls ein Slice die Namen braucht, zuerst `slice-declare-df-standardwert-vorhandene-spalte`.
12. **Prüfung des Verweises (3725):** ein Fremdschlüssel, der einen Schlüssel der Tabelle referenziert, hindert das Entfernen des Schlüssels am echten Server (3725, danach 3727); die Bibliothek prüft keine referentielle Integrität und entfernt ihn. Trigger: die Bibliothek erhält eine Prüfung von Verweisen zwischen Tabellen (nicht geplant).
13. **Antwort auf `DROP INDEX` im Einzelnen:** (a) der Abschluss der Erfolgsantwort ist die Art `UNKNOWN` (`DONE` mit `COUNT` 0, Kennung 0), der echte Server antwortet mit `0x00c9` ohne `COUNT`, und auf `CREATE INDEX` mit `0x00c8` ohne `COUNT` (gemessen, vier Anweisungen je Instanz: gewöhnlich, eindeutig, zweispaltig; `INCLUDE`, Filter und absteigende Spalte nicht). Entscheid des Nutzers am 2026-11-12 per Auswahl: die öffentliche Aufzählung `StatementKind` ([`SPEC-059`](../../../../../../spec/spezifikation.md#einstieg-des-integrators-vertrag-zu-spec-059)) bekommt `CREATE_INDEX` (`0x00c8`) und `DROP_INDEX` (`0x00c9`), beide ohne `COUNT` (Muster `CREATE_TABLE` und `ALTER_TABLE`); Träger ist der eigene Folge-Slice [slice-statementkind-index-mitglieder](../../../in-progress/slice-statementkind-index-mitglieder.md), in `slice-drop-index-if-exists` bleibt es bei `UNKNOWN`. (b) Das `DONE` nach 3701 trägt bei der Bibliothek `0x00fd` (Server `0x00c9`), und für eine unbekannte Tabelle ohne `IF EXISTS` sendet die Bibliothek State 7 (Server State 6). Beides braucht keine öffentliche Fläche (`ErrorRule` ist intern) und ist nicht gebaut: der Befehl des `DONE` nach einem Fehler gilt für jeden Code des Sequenzierers, State 6 verlangte einen eigenen Fehlercode. Trigger für (b): ein Client, der Befehl oder State auswertet.
14. **Entfernen eines eindeutigen Index durch d-migrate:** nimmt das Soll einen Index weg, den d-migrate als Eindeutigkeit gelesen hat (Punkt 3), sendet es `ALTER TABLE … DROP CONSTRAINT IF EXISTS <Index>`; der Testserver führt den Namen als Index, der Text ändert nichts, und `schema migrate --execute` endet mit Exit 5 (`POST_EXECUTE_DRIFT`). Ob der echte Server den Index dabei entfernt, ist nicht gemessen (Messprotokoll [drop-index-d-migrate-2026-11-11](../../../../../messungen/drop-index-d-migrate-2026-11-11.md), Tabelle C, t12 bis t14). Trigger: die Abnahme [slice-abnahme-d-migrate](../../../open/slice-abnahme-d-migrate.md).
