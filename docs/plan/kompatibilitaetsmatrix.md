# Kompatibilitätsmatrix: Nachrichten und Datentypen des Codecs, Modulgrenzen

Abdeckungs-Dokument zu [TDS-QA-05](../../spec/lastenheft.md#tds-qa-05--wartbarkeit) (Wartbarkeit: unterstützte Nachrichten und Datentypen sind dokumentiert, Protokollverarbeitung und Backendintegration getrennt testbar). Es liegt in `docs/plan/` (`AGENTS.md` §5 Regel 6) und **weist nach**: ein Beleg ist ein bestandener Testfall, kein Verweis.

**Gegenstand:** was der gebaute Codec (`protocol/prelogin`, `protocol/login7`, `protocol/sqlbatch`, `protocol/rpc`, `protocol/token`, `protocol/wire`, `protocol/session`) und der Transport (`transport/framing`, `transport/messaging`, `transport/channel`, `transport/tls`) heute kann. Die Spalte „Test“ nennt `Klasse > Testfall` in der Schreibweise der Gradle-Ausgabe.

**Stand des Belegs:** `docker build --target test --no-cache-filter test`, Basis ist der Merge-Stand `bda6cd6`: 280 Testfälle in 37 Klassen, alle bestanden, keiner rot, keiner übersprungen. Ein Zitat in dieser Datei gilt nur für diesen Lauf; die Datei nennt den Stand, sie hält ihn nicht fest, und wer sie ändert, lässt den Lauf neu laufen und prüft die Zitate (Abschnitt „Pflege“).

**Referenzclient: nicht gemessen.** Keine Zeile dieser Matrix belegt, dass der .NET-Referenzclient (`Microsoft.Data.SqlClient` 7.1.1) die Aussage annimmt. Das Projekt `referenztest-dotnet` enthält allein `KeinServerSmokeTests`, es spricht mit keinem Server. Träger der Messung am Referenzclient sind `slice-qa-kompatibilitaet` und `slice-qa-reproduzierbarkeit`.

## Herkunft der Aussage

Die Spalte „Herkunft“ nennt, wie weit die Aussage trägt. Die Stufen aus den Closure-Notizen von `slice-codec-tds-paket`, `slice-codec-rpc-parser` und `slice-transport-tls-schleife`:

| Stufe | Bedeutung |
|---|---|
| gemessen (Spike) | am Spike-Testserver mit dem Referenzclient beobachtet ([ADR-0005](adr/0005-rpc-und-prepared-statements.md), Messmatrix): TDS 7.4 unverschlüsselt, ohne Pool, kein Microsoft-SQL-Server, ein Lauf, Spike-Code nicht im Repo. Der Test im Repo pinnt den Wert und misst nichts |
| gemessen (JDK-Gegenstelle) | gegen eine JDK-`SSLEngine` im selben Prozess beobachtet, nicht am Referenzclient |
| Handvektor | von Hand aus der Lesart von MS-TDS gerechnet; der Text von MS-TDS liegt nicht im Repo; eine Lesart, keine Messung |
| Selbstkonsistenz | Code gegen Code (Roundtrip, Fuzz mit festem Startwert); belegt keine Protokolltreue |
| Festlegung | Setzung ohne Messung und ohne unabhängigen Vektor, im KDoc des Elements so gekennzeichnet |
| nicht gemessen | ausdrücklich ungeprüft |

## Pflege

Die Matrix wird von Hand gepflegt. Ein Erzeuger bräuchte ein neues Tag in jedem Testkopf oder eine zweite Zuordnungsdatei; `make spec-abdeckung` führt die Abdeckung der Festlegungen von `spec/spezifikation.md` und ist an Nachrichten und Typen nicht gebunden. Es gibt kein Gate für diese Datei.

Wer sie ändert, lässt `make test` mit frischem Testlauf (`docker build --target test --no-cache-filter test --progress=plain .`) laufen und prüft, dass jedes `Klasse > Testfall` aus Spalte „Test“ im Bericht als `PASSED` steht. Eine Zeile „unterstützt“ ohne so einen Testfall ist eine Zeile „nicht belegt“ und trägt diesen Status.
